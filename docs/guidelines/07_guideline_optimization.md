# 7) 지침 최적화 운영 규칙

본 문서는 지침 문서와 실행 스크립트 전반의 중복·충돌을 점검하고, 필요한 경우 최소 변경으로 정리하는 절차를 정의한다. 최적화(점검/수정)는 사용자가 명시적으로 요청할 때에만 수행한다.

## A. 목적과 범위
- 목적: 응답 지연을 줄이고 유지보수를 쉽게 하기 위해 지침의 중복·불일치·불명확한 소유 범위를 정리한다.
- 범위: `docs/guidelines/` 하위 모든 문서, 연관 보조 문서(cheatsheet, glossary), 관련 Python 스크립트(`scripts/`)의 정책적 동작.

## B. 실행 조건과 산출물
- 실행 조건: 사용자가 “지침 최적화 실행”, “중복 점검 실행” 등 명령형으로 요청한 경우에만 수행한다.
- 산출물(반드시 보고):
  1) 변경 요약(무엇을/왜)  2) 파일별 변경 리스트(파일:라인)  3) 되돌리기 방법  4) 영향 범위(참조 링크·스크립트)  5) 후속 TODO.

## C. 준비 단계(인벤토리·소유권 맵)
1. 인벤토리: `docs/guidelines/*` 파일 목록과 최상위 헤더(제목), 핵심 섹션을 수집한다.
   - 예: `rg -n "^#|^## " docs/guidelines`
2. 소유권 맵 작성(임시 표): 각 문서가 “정식으로 소유”하는 주제를 1–3개로 제한해 명시한다.
   - 권장 기본 소유권
     - 01 LLM 운영 규칙 → 운영 플로우/언어/링크 표기 규칙
     - 02 시각화 지침 → 모든 플롯/지도 규칙(스타일·검증 포함)
     - 05 저장·출력 지침 → 저장 경로/외장/동기화/출력 포맷
     - 06 과학 커뮤니케이션 → 근거·인용·발표 규칙
     - 용어집(glossary) → 용어 정의·주의사항

## D. 중복 점검 규칙
1) 단일 문서 내 중복
- 동일·유사 문장이 두 번 이상 반복되는지 확인(헤더·불릿 기준).
- 규정·체크리스트가 두 위치 이상에 흩어져 있으면 한 곳으로 병합하고 다른 곳은 링크만 남긴다.
- 도구 예시: `rg -n "키워드" docs/guidelines/01_llm_guidelines.md`, `rg -n -i '경로|path|링크' <파일>`

2) 문서 간 중복
- 소유권 맵을 기준으로 타 문서의 고유 주제를 침범한 섹션을 식별한다.
- 조치 우선순위
  - a. 내용이 동일/유사 → 비소유 문서에서는 한 줄 링크로 대체(“자세한 규칙: …”).
  - b. 내용이 상충 → 소유 문서를 기준으로 정합화하고, 비소유 문서에는 예외·포인터만 남긴다.
- 도구 예시: `rg -n -i '경로 표기|path notation|저장.*기본값|플롯 체크리스트' docs/guidelines`

3) 파이썬 스크립트와의 중복/불일치
- 정책적 동작(기본 출력 경로, 링크 표기 형식, 저널 루틴 등)이 스크립트로 구현된 경우, 문서에는 “정의”보다 “참조와 사용법”만 유지한다.
- 스크립트가 사실상의 규범이면 스크립트를 “정본(canonical)”로 지정하고 문서는 레퍼런스 링크를 제공한다.
- 점검 포인트
  - `scripts/journal_start.py`, `scripts/journal_end.py`, `scripts/log_tmp_note.py`의 출력 형식·옵션이 문서 규칙과 일치하는가?
  - 시각화 스크립트(`scripts/plot_*.py`)의 기본 저장 경로·포맷이 05 지침과 일치하는가?
- 도구 예시: `rg -n "journal|notes|MLHB/|dir:" scripts`, `python3 scripts/journal_start.py -h || true`

## E. 수정 적용 원칙(최소 변경·참조화)
- 원칙 1: “정본 1곳”만 상세 규정 보유, 나머지는 링크·요약만 유지.
- 원칙 2: 운영 흐름은 01에, 시각화는 02에, 저장은 05에, 과학 커뮤니케이션은 06에 집중한다.
- 원칙 3: 재서술 대신 “참조”를 선호한다. 동일 규칙을 다시 적지 않는다.

## F. 변경 절차(되돌리기 보장)
1. 변경 전 스냅샷: 변경 대상 파일을 `docs/guidelines/_archive/YYYYMMDD/<파일명>`에 백업.
2. 변경 적용: 중복 제거/섹션 이동/링크 삽입.
3. 변경 기록: `docs/guidelines/CHANGELOG.md`에 항목 추가(날짜, 파일, 요약, 이유, 영향, 되돌리기 경로).
4. 되돌리기: 백업본을 원위치로 복사하고 CHANGELOG에 리버트 기록 추가.

## G. 보고 규칙(사용자 보고서 형식)
- 개요: 총 변경 수, 영향 문서, 예상 효과(응답 지연·유지보수성).
- 상세: 파일별 변경 불릿(각 `path:line`), 삭제/이동/링크화 구분.
- 확인 항목: 스크립트 동작과의 정합성 체크 결과, 링크 검증 결과.
- 되돌리기 안내: 백업 경로, 복원 명령 예시.

## H. 자동화·도구(선택)
- 중복 탐지(라인 레벨): `rg -n "정규식" docs/guidelines | cut -d: -f3 | sort | uniq -d`
- 헤더 비교: `rg -n "^## " docs/guidelines | sed 's/.*## //' | sort | uniq -d`
- 키워드 매핑표 생성: `rg -n -i '경로|저장|플롯|근거|인용' docs/guidelines`
- 스크립트 옵션 수집: `rg -n "argparse|ArgumentParser|add_argument" scripts`
- 제안(옵션): `scripts/audit_guidelines.py`를 작성해 인벤토리/소유권 맵/중복 리포트를 자동 생성.

## I. 권장 메타데이터
- 각 문서 상단에 다음 메타를 추가 추천: `owner:`, `canonical:`, `depends_on:`, `last_review:`.

## J. 체크리스트(실행 시 사용)
- [ ] 인벤토리/소유권 맵 작성 완료
- [ ] 단일 문서 내 중복 제거/병합
- [ ] 문서 간 중복 정리(정본 링크화)
- [ ] 스크립트와 정합성 검토(정본 지정)
- [ ] 링크 검증 완료(상대경로/클릭 확인)
- [ ] 백업/CHANGELOG/되돌리기 안내 작성

## K. 추가 권고안
- `docs/guidelines/README.md`에 소유권 맵 요약을 게시해 신규 작성자가 혼선 없이 확장하도록 한다.
- 자주 바뀌는 규칙은 별도 “참조 모듈(스크립트)”로 표준화하고 문서에서는 원칙·사용법만 유지한다.
