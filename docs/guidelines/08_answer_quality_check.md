# 8) 답변 품질 사전 점검(QA) 지침
<!-- owner: MLHB-core; canonical: true; depends_on: docs/guidelines/01_llm_guidelines.md, docs/guidelines/06_scientific_communication.md; last_review: 2025-09-30 -->

## A. 목적·적용 범위
- 목적: 답변이 “증거(파일/수치) 기반·내부 경로 우선·명확한 한국어”를 충족하는지 출고 전에 60초 내 점검한다.
- 범위: 코드 설명, 분석 결과 요약, 운영 변경 보고, 슬라이드 초안 요약 등 대부분의 응답.

## B. 출고 전 퀵 체크(60초)
- [ ] 내부 근거가 있는가? (파일·경로·라인 또는 코드 식별자)
- [ ] 모호/추측 표현이 없는가? (예: “아마/대충/그런 것 같음”)
- [ ] 단위·수치가 맞는가? (MLHB: K s⁻¹↔K day⁻¹ 전환시 ×86400 명시)
- [ ] 링크가 내부 우선인가? (외부 웹은 요청 시만, 내부 경로는 상대경로)
- [ ] 한국어로 간결·구조화되어 있는가? (불릿/섹션 활용, 중복 제거)
- [ ] 시간 기록이 있는가? (임시 메모 시각 또는 `HH:MM–HH:MM` 구간)

## C. 규칙 상세(요지)
1) 내부 근거 표기
   - 파일 참조: `repo-상대경로:라인` 권장(예: `src/process_d2nf.py:612`).
   - 또는 코드 식별자/옵션: 함수·클래스·CLI 옵션명 등(`--we-mode`, `--adv-scheme`).

2) 언어·표현
   - 한국어 사용. 모호 표현 금지: “아마, 대충, 그럴 수도, ~같음, maybe, probably”.
   - 결론은 단정적으로, 가설은 “가설/추정”임을 명시.

3) 단위·수치
   - MLHB 변수의 저장 단위 확인(K day⁻¹). 텍스트 설명에서 K s⁻¹ ↔ K day⁻¹ 변환 시 `×86400` 명시.
   - MLD/옵션 언급 시 키워드 동반: `we-mode`, `Δσ0`, `mld-source`.

4) 링크 정책
   - 내부 우선(상대경로). 외부 웹은 사용자가 요청한 경우에만 사용하고, 저널/지침에 내부 PDF/경로가 있으면 그쪽을 우선.

5) 시간·결정 기록
   - 결정/옵스 변경/실험 이벤트는 임시 메모 시각 또는 일지 내 `HH:MM–HH:MM` 구간으로 확인 가능해야 한다.
   - Issues & References의 결정 요약은 해당 임시 메모(시각) 링크를 포함한다.


## D. 예시
- 좋은 예: “엔트레인먼트 항은 `src/process_d2nf.py:740`에서 계산하며, 출력 단위는 K day⁻¹입니다. 플롯 시 ×86400은 불필요합니다.”
- 나쁜 예: “엔트레인먼트는 아마 깊어질 때만 작동해요. 자세한 건 코드 보세요.”

## E. 도구(자동 점검)
- `python3 scripts/audit_answers.py --in <file>` 또는 `... < text | python3 scripts/audit_answers.py`
  - 출력: 규칙별 Pass/Fail, 개선 메시지, 요약 점수(선택).
- 주간 집계(선택): `journal_weekly.py`에 Pass율/위반 Top3 삽입 가능(요청 시 도입).
