## 증상
GrADS에서 아래와 같은 오류가 발생하며 `d qnet`가 실패함.

```
gancgrid error: nc_get_vara_double failed; NetCDF: HDF error
Data Request Error:  Error for variable 'qnet'
DISPLAY error:  Invalid expression
  Expression = qnet
```

## 원인
- 변수명 대소문자: MLHB 산출 NetCDF의 변수명은 `QNET`(대문자)임. GrADS SDF 인터페이스에서 변수명이 실제 NetCDF 이름과 일치하지 않으면 위와 같은 오류가 나올 수 있음.
- 시간축 선택 오류: 이전 버그로 월별 파일의 `time`이 1개만 기록된 상태(`time = UNLIMITED ; // (1 currently)`)에서 `set t 2`가 설정되어 있거나 기본 `t=2` 환경이면 `d QNET`이 실패함(유효하지 않은 time 좌표).
- 파일 자체 일관성: 과거에는 월별 덮어쓰기 중 `time` 축이 유지되지 않아 HDF I/O 에러를 유발. 현재는 concat→재쓰기 + `.tmp`→rename로 해결됨(관련 노트 참조).

## 해결
1) 변수명 확인: GrADS에서 `q file`로 변수 목록을 확인하고, 실제 이름(`QNET`)을 사용.
2) 시간축 초기화: `q time`으로 가용 시간 확인 후 `set t 1`부터 조회.
3) 최신 파일 재생성: 월별 파일이 오래된 형식이면 `scripts/run_mlhb_monthly.py` 최신판으로 재생성.
4) 점검 루틴: `ncdump -h <file>.nc`로 `time`이 `UNLIMITED`이며 여러 시점이 누적되었는지 확인. GrADS `q time`도 함께 확인.

## 예방
- 월별 집계는 항상 기존 파일에 concat 후 `.tmp`→rename(원자적 저장)을 사용.
- GrADS 세션 시작 시 `q file`/`q time`을 먼저 실행해 변수명/시간축을 확인한 뒤 `d <VAR>`를 호출.
