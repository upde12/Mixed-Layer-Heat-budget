## 상황 요약
- MLHB 일일/월별 파이프라인을 점검하던 중 `--hmin` 분모 하한 옵션이 여전히 코드·문서·스크립트에 남아 있는 것을 확인했습니다.
- 최근 운영 결정으로 분모 하한을 사용하지 않고 0 또는 결측 두께는 NaN으로 처리하기로 했으므로, 해당 옵션이 남아 있으면 혼선과 재발 활용 위험이 있습니다.

## 에러 메시지
```
(직접적인 예외는 없었지만, 과거 로그/스크립트에서 `--hmin 15`가 기본 포함되어 분모가 강제로 클램프되는 문제가 재발할 수 있는 상태였습니다.)
```

## 원인 진단
- 초기 안정화 단계에서 추가했던 `--hmin`이 문서와 러너 예시에 그대로 남아 있어 "기본값"처럼 보였습니다.
- 코드도 `H0 < hmin`일 때 분모를 강제로 하한에 맞추고 NetCDF 전역 속성으로 기록해, 결정과 배치가 불일치했습니다.

## 해결 절차
1. `src/process_d2nf.py`에서 `HMIN_DEF`, CLI 파라미터, NetCDF 속성, 분모 클램프 로직을 제거하고 `hden<=0`은 NaN으로 유지하도록 수정.
2. 월별/비교/이류 스크립트(`run_mlhb_monthly*.py`, `run_adv_schemes.py`)에서 `--hmin` 인자를 삭제.
3. 요약/매뉴얼/논의 문서에서 하한 언급을 "분모 하한 없음"으로 교체하고 실행 프리셋을 정리.
4. Changelog, 연혁, QA 체크리스트, 일지에 결정 사항을 기록.

## 예방 및 메모
- 분모 하한은 재도입하지 않으며, 얕은 혼합층의 품질 이슈는 NaN 모니터링과 후처리 필터로 대응합니다.
- 문서 예시와 코드 기본값이 어긋나지 않도록, 인터페이스 제거/변경 후에는 Changelog와 QA 규칙을 동시에 갱신합니다.
- 향후 안정화 옵션이 필요해도 문헌 근거와 유지 기준을 먼저 정리하고 도입합니다.
